# 核心 Prompt 与实际过程记录

后续补充：本轮功能复核及真实验证新增指令见文末07、08；用户填写的密钥不纳入Prompt或记录。

本文件在开发开始创建，后续按真实执行追加。以下是本轮交给编码代理的阶段指令，包含从用户规格拆出的原始任务片段；并非声称在 Claude Code 中执行过。运行时角色 Prompt 独立保存在 server/prompts.ts。

## 09 · SDD / TDD · 有据总结与一致性

> 继续把总结夸大共识、讨论边界和时间线不一致的问题修好，再补做长上下文压缩压力测试，检查关键条件和分歧是否丢失。修复后跑真实讨论回归，并更新验收报告。

意图：将自由总结改成按支持者和原文装配；发言提交前检查，冲突重写一次仍失败则暂停；旧分歧必须有新明确确认才能关闭。先建立缺失模块的失败用例，再实现并验证，保留实际契约失败和同场恢复证据。

## 10 · E2E · 压缩保真与真实讨论回归

> 检查关键条件和分歧是否丢失。修复后跑真实讨论回归，并更新验收报告。

意图：分别验证程序是否保留证据，以及真实模型能否读出证据。使用明确标识的40/180/600条合成历史做预算压力，另对同一24条资料的完整/压缩版本做2次真实读取；普通真实讨论独立回归，不用合成资料冒充真实长讨论。发现引用契约问题后补充错误分类、来源ID归一与定向重试。

## 01 · SDD · 规格

> 面向需要评审产品或技术方案的用户，提供一间由 AI 主持人和多位 AI 专家共同参与的演播厅。创建讨论 → 生成阵容 → 用户确认 → 主持人开场 → 专家自主参与 → 持续更新共识与分歧 → 主持人总结 → 返回查看记录。

意图：以用户确认的产品规格建立状态机和验收边界。挑战：区分真实模型证据、测试替身和人工示例，必须诚实标识来源。

## 02 · SDD · 数据与 API

> 采用 React + TypeScript 前端、Node.js + Fastify 后端、SQLite 数据库、SSE 实时通信。所有实体查询、状态和事件均以 discussionId 隔离。客户端按事件序号去重；断线重连通过快照与后续事件恢复。

意图：先固定共享类型、数据库与 API 契约。修正方向：事件和数据变更一并事务提交，客户端使用快照游标抵御重连与旧请求覆盖。

## 03 · DDD · 组件与页面

> 演播厅采用固定视口布局：左侧专家状态、中间现场讨论、右侧讨论成果。窄屏使用三个页签切换内容，各页签内部滚动。新发言到达后自动跟随到底部；用户向上翻阅时停止跟随。

意图：围绕观看体验实现独立功能组件和设计 token。修正方向：状态控制、生成失败和空数据均为实际交互，不将概念图作为页面背景。

## 04 · TDD · 调度与可信成果

> 每轮采用“申请发言 → 选择发言者 → 正式发言”的流程。禁止通过专家数组下标轮流发言。共识必须有至少两位不同专家的明确支持，且不存在尚未处理的直接反对意见。

意图：先用固定参与意向和正文引用构造测试，再实现选择、引用校验、共识证据验证与撤回。重点验证第二位专家能读到本轮第一位的新发言。

## 05 · TDD · 恢复与隔离

> 同一讨论只允许一个调度任务运行；不同讨论可以独立推进。单次模型调用超时或结构校验失败，自动重试一次；仍失败则暂停该场并提供重试入口。重复点击不得产生重复任务或重复总结。

意图：用故障注入覆盖暂停边界、模型异常、检查点恢复、并发与重启。失败后只重试未完成步骤，不重复已提交发言。

## 06 · E2E · 质量闭环

> 从新建到总结全流程通过，并能返回首页重新打开记录。断线重连无重复消息；页面不整体滚动；不泄露内部事件、JSON、密钥或隐藏推理。

意图：浏览器跑完整用户路径，检查桌面和手机布局，并保留真实执行的验证结果。真实模型未配置时不得把替身通过算成真实冒烟通过。

## 07 · TDD · 原图约束复核

> 每次发言控制在1–2句；现场Transcript显示发言人姓名与职业/Title，不显示“举手”等内部事件。

意图：按用户再次提供的原图补齐后端句数校验和小屏身份展示。先观察新测试因缺少约束模块失败，再实现校验及重试，修正演示适配器，浏览器断言手机职业/Title可见。

## 08 · E2E · 真实模型与归档验收

> 先帮我创建好.env配置文件，我来填写API Key、接口地址和模型ID。填好后你帮我切换到真实模式，先跑一场短讨论，检查上下文承接、共识分歧和数据库保存是否正常。

意图：配置仅存本机，真实调用与演示分开。实际遇到输出截断，补记结束原因和白名单用量后定位预算耗尽，以同一场恢复验证消息不重复；保留内容质量风险而不把结构通过等同语义完全正确。

## 09 · TDD / E2E · 条件、范围与时间线追加回归

> 继续把总结夸大共识、讨论边界和时间线不一致的问题修好，再补做长上下文压缩压力测试，检查关键条件和分歧是否丢失。修复后跑真实讨论回归，并更新验收报告。

先添加时间线阶段顺序、跨句例外及全员归因反例，实际观察失败后再修复；将600条合成历史的压缩结果交给真实模型检索原句与来源。真实产品讨论中遭遇引用失败与热重启暂停，保留失败并恢复同一场；结构核对通过后逐条审阅，额外披露保守关闭造成的历史待确认记录滞留，不用测试数量掩盖语义限制。

## 10 · DDD / TDD / E2E · 圆桌工作区改造

> 类codex的布局，左侧是不同的主题讨论的会话框，能随时新建讨论组，中间的大屏底部输入具体的讨论主题和确定专家人数。允许用户随时去调整主题讨论方向；不同的专家Agent不是要按顺序发言的，而是同步思考，可以补充，抢答，反驳；放开讨论次数，确保收敛同时不能无限扩大，确定一个结束边界机制。

这是用户原请求节选；完整草图与目标在本会话。沿用生成概念后实现原生节点、独立窗口、可折叠成果、方向输入与多组侧栏；先用屏障测试证明意向并行和正式发言上下文更新，再跑5条新E2E。实际修正了方向更新时的过期结果、结束边界丢弃方向、阵容过时仍可确认和手机标签相撞。

后续工程修正并非补写用户原始Prompt：真实模型回归发现默认高推理导致输出截断、28,000字符不足保护第15次发言的完整证据，分别增加显式非思考配置和56,000字符预算，保留失败并恢复原场。逐条语义审阅又发现两人字面引用不能证明相同阶段共识、旧分歧关闭时序过严，因此补充共同判断逐来源审查与归档前逐ID复核及相应反例。原始失败、真实结果、截图和量化数据保存在evidence目录，详见WORKSPACE-ACCEPTANCE.md。

## 11 · TDD / E2E · 稳定议题账本与原文支持

> 继续把历史分歧重复、已关闭记录滞留和共识少报的问题修好，再跑一场真实讨论回归，重点检查分歧能否正确关闭、共识是否有原文支持，并更新验收报告。

以上为本轮用户原始任务。工程拆分：先为身份复用、旧引用、双向确认、合并墓碑、关闭重开与共识遗漏编写反例，再实现增量账本、独立语义审核和同事务归档。真实失败促使移除重复的旧关闭协议；原话能够逐字引用还不等于支持整个复合结论，保留未验证候选，未强行把它们升级为成功。

本轮工程提示摘录（实现中使用的设计约束，不冒充用户原话）：

> A明确提出某原子条件，B后来完整接受，即已有A的support与B的accept两方证据；无需A再回应“我同意你接受我的原提议”。若B同时改动条件，仅对完整接受的原子部分成立，新增条件仍待确认。

真实模型、具体异常及回归证据见INSIGHT-LEDGER-REGRESSION.md。代码中的最终原始系统提示保存在server/prompts.ts；过程快照保留在docs/evidence/ledger-*.json。
