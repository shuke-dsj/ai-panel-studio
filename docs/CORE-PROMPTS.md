# 核心 Prompt · 提交版

以下是历史用户指令和产品规格原文节选，省略其余段落。阶段标签与说明为交付整理时所加。完整过程记录见 [PROMPTS.md](PROMPTS.md)，产品运行时的角色及审核指令在 [server/prompts.ts](../server/prompts.ts)。

## 1 · SDD · 业务规格与数据/API 契约

> 采用 **React + TypeScript 前端、Node.js + Fastify 后端、SQLite 数据库、SSE 实时通信**。通过后端模型适配层接入真实服务，API Key 仅从后端环境变量读取。
>
> 发言意向为临时调度数据，不作为 Transcript 内容。所有实体查询、状态和事件均以 `discussionId` 隔离。

对应共享类型与 API 契约。为处理跨场隔离和重连，快照返回场内游标，领域变更与事件在同一事务中保存。

## 2 · DDD · 页面和交互组件

> 顶部展示话题、讨论状态、发言进度，以及暂停/继续、提前结束操作。窄屏使用三个页签切换内容，各页签内部滚动。
>
> - 新发言到达后自动跟随到底部；用户向上翻阅时停止跟随，提供“查看最新发言”。

将讨论内容、专家状态、成果与控制操作拆成独立组件。后续按用户工作区交互改为可打开的专家窗与窄屏成果抽屉，保留固定视口与阅读位置约束。

## 3 · TDD · 证据和最新立场

> 继续把历史分歧重复、已关闭记录滞留和共识少报的问题修好，再跑一场真实讨论回归，重点检查分歧能否正确关闭、共识是否有原文支持，并更新验收报告。

用同义重复、证据撤回、待确认转共识等反例约束账本行为。原句能被找到只证明引用存在，还要核对说话人是否支持同一原子条款。

## 4 · TDD · 收敛判定与异常恢复

> 先把收敛机制修好：第12次发言只触发评估，别自动切到收敛阶段；还有能靠讨论解决的问题就继续追问，判定格式或引用出错也别中断（总是会出现这样的错误，什么格式引用错误解析错误等等，你去修一下，为什么会出现这样的问题？）。顺便修正把「待确认转共识」算作「已关闭分歧」的问题。

分开评估触发门槛、追问限额与真实结束原因，并测试错误兜底。关闭指标要求存在此前已验证的分歧历史。

## 5 · E2E · 真实短讨论与数据库

> 先帮我创建好 .env 配置文件，我来填写 API Key、接口地址和模型 ID。填好后你帮我切换到真实模式，先跑一场短讨论，检查上下文承接、共识分歧和数据库保存是否正常。

按同一场次核对 API 快照、SQLite 原文和结束事件。首次真实输出截断后，从保留的检查点恢复并检查原有消息 ID，确认不会重复生成。

## 6 · E2E · 压缩保真与质量回归

> 继续把总结夸大共识、讨论边界和时间线不一致的问题修好，再补做长上下文压缩压力测试，检查关键条件和分歧是否丢失。修复后跑真实讨论回归，并更新验收报告。

将程序级压力测试和真实语义验证分开，分别对照预算、引用 ID 与关键原句。复核发现仍有保守漏报，于验收报告保留边界。
