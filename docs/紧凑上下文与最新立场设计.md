# 紧凑上下文与最新立场验收 · 2026-11-18

## 专家如何取得上下文

一场讨论使用同一后端模型。申请发言的专家并发读取同一份快照。选中的专家分别生成正式发言，下一位看到前一位刚落库的原话。共享内容包括有效议题和前提、阵容、实际发言、可引用的原话证据、分歧账本和仅用于导航的滚动摘要。动态部分是当前角色、指令、参与意向、活动焦点和当前任务数据。模型通过角色 ID 找到对应的职业、立场和关注领域。UI 显示可公开的观点与状态。

本轮 `compact` 将共享快照组织为固定头、按序追加的逐条发言及衍生账本。保留消息 ID、顺序、作者、原文、回复关系和证据。省略每条发言重复的讨论 ID、时间戳和压缩诊断计数。角色包与共享阵容完全相同时只传角色 ID。不同任务和专家继续使用同一个请求入口与公共前缀。加接口或换 Key 没有已验证的缓存收益。

## 小样本

每种布局四次请求，包含两次原文提取和两位专家各一次回应。保真检查覆盖关键条件的逐字原句、真实来源 ID 与未决分歧。经追加发言后，两个布局均通过原文提取。该公开合成样本用于检查条件承接，并非完整的发言质量或角色区分评分。

## 证据修正

独立审核同时覆盖已发布共识和已发布分歧，即使本轮提取器没有提出修改。若议题候选同时引用一位专家的旧反对和同题更晚接受，服务端拒绝旧反对仍有效的候选。独立审核若用真实专家原话指出已发布条目失效，条目移至待复核，原历史仍在。收窄后重新发布需满足原话、作者、参与方和同题时序约束。总结使用已验证的当前投影，另外标记待外部确认和待复核。

两专家六条发言的定向回放共四次真实调用。旧「Redis 直接派发」立场从当前分歧移除，按第 5、6 条最新原文确认「Redis 只唤醒，outbox 领取」。旧「两人同意审批权限和全部审计字段」从共识移除。明确只允许归因两位专家都支持的最小条款。本次回放未发布更窄的审计留痕共识，说明漏报仍可能发生。证据位于本地 `data/evidence-latest-position-probe.json`。
